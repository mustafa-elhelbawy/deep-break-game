### Step 2 — Add setup methods

```gdscript
## Enable mobile (collapsing) mode. Call AFTER add_child() from BrickGrid.gd.
## speed: fall speed in pixels per second.
func set_mobile(speed: float) -> void:
	_collapse_speed = speed
	_is_mobile = true
	# Apply a slight red tint as a visual warning to the player.
	# modulate multiplies the existing sprite colour component-wise.
	# (1.2, 0.75, 0.75) shifts toward red without completely changing the tier colour.
	# [JS equiv]  this.sprite.style.filter = 'sepia(0.3) hue-rotate(-30deg)'
	$Sprite2D.modulate = Color(1.2, 0.75, 0.75)

## Set the Y position (world space) that triggers the reached_paddle signal.
## Called by Game.gd immediately after spawning each mobile brick.
func set_paddle_y(y: float) -> void:
	_paddle_y = y
```

### Step 3 — Add physics movement

Add or extend `_physics_process()`:

```gdscript
func _physics_process(delta: float) -> void:
	if not _is_mobile:
		return  # static brick — no movement

	# Move downward each physics frame.
	# +Y = downward in Godot 2D.
	# [JS equiv]  this.y += this._collapseSpeed * delta
	position.y += _collapse_speed * delta

	# Check if brick has reached the paddle zone.
	# global_position.y accounts for any parent transforms (BrickGrid may be offset).
	# [JS equiv]  if (this.globalY >= this._paddleY) this.emit('reachedPaddle')
	if global_position.y >= _paddle_y:
		# Emit signal — Game.gd handles the life-lost logic.
		emit_signal("reached_paddle")
		# Remove the brick immediately after signalling.
		queue_free()

	# Also remove if off the bottom of the screen (missed the paddle — no life lost).
	# CRITICAL: emit drifted_off BEFORE queue_free so BrickGrid can trigger _check_cleared.
	# Without this, if the last brick drifts off silently, the level never clears. (BUG-2)
	# [JS equiv]  if (this.globalY > screenH + 20) { this.emit('driftedOff'); this.remove() }
	var screen_h: float = get_viewport().get_visible_rect().size.y
	if global_position.y > screen_h + 20.0:
		emit_signal("drifted_off")
		queue_free()
```

**Add the handler method** (alongside `_on_brick_hit` and other brick relay handlers):
```gdscript
func _on_brick_drifted_off() -> void:
	# Defer so the brick's queue_free() completes before we count remaining bricks.
	call_deferred("_check_cleared")
```

### Step 4 — Ensure ball still collides correctly

The `StaticBody2D` with a position that changes each frame is NOT seen as moving by the physics engine (unlike `AnimatableBody2D`). This means the ball will still bounce off it, but the collision normal may lag by one frame when the brick is falling fast.

For the speed ranges in this game (30–90 px/s over ~16 ms frames = 0.5–1.4 px/frame) this lag is imperceptible. No architecture change needed — keeping `StaticBody2D` is correct and simpler.

> If future levels require very high collapse speeds (>200 px/s) and tunnelling occurs, the fix is to switch to `CharacterBody2D` + `move_and_collide()`. That is out of scope for Phase 6.
