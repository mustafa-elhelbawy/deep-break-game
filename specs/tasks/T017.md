### Checklist — run the app and check each item

#### Startup
- [ ] App launches without crashing (no "App has stopped" dialog)
- [ ] Screen shows **dark navy background** — not pure black, not white, not grey
- [ ] Cyan paddle bar visible near the bottom of the screen
- [ ] Small white circle (ball) visible just above the paddle
- [ ] Ball is NOT moving — waits for a tap

#### Touch Paddle Control
- [ ] Place thumb in **lower half** of screen and drag left → paddle moves left
- [ ] Drag right → paddle moves right
- [ ] Drag speed feels **immediate** — no perceptible lag between finger and paddle
- [ ] Paddle stops at left edge — does not go off-screen
- [ ] Paddle stops at right edge — does not go off-screen
- [ ] Touch in **upper half** of screen → paddle does NOT move
- [ ] Lift finger → paddle stays at last position (does not snap to centre)

#### Ball Launch + Bounce
- [ ] Tap screen → ball launches upward at an angle
- [ ] Ball bounces off **top wall** — angle changes, no tunnelling
- [ ] Ball bounces off **left wall** — correct reflection
- [ ] Ball bounces off **right wall** — correct reflection
- [ ] Ball bounces off **paddle** when paddle is positioned under it
- [ ] Ball speed feels consistent across multiple bounces (no acceleration)

#### Ball Lost + Reset
- [ ] Let ball fall past paddle → ball disappears off the bottom
- [ ] Ball reappears above the paddle within 1 frame (no visible delay)
- [ ] Tap again → ball launches normally (loop repeatable)

#### Performance
- [ ] Play for 60 seconds continuously — no frame drops visible to the eye
- [ ] Device does not get notably warm during 60-second play (minimal GPU load)

---

### Performance Profiling (optional but recommended)

For a mid-range device check, use Android GPU Inspector or Godot's built-in profiler:

**Godot remote profiler** (requires USB + Godot editor open on Mac):
1. With device connected and APK running, open Godot editor
2. Debug → Connect to Running Instance
3. Profiler tab → check "Frame Time" values
4. Target: frame time ≤ 16.7 ms (= 60 fps) sustained

**Android GPU Inspector** (standalone):
1. Install from developer.android.com/agi
2. Launch, connect to device, capture a frame during active play
3. Check draw call count — should be ≤ 10 in Phase 1 (ball + paddle + background only, no bricks yet)

### Known Acceptable Differences vs Mac Editor

| Behaviour | Mac editor | Android device | Expected? |
|-----------|-----------|----------------|-----------|
| Touch input | Mouse emulates touch | Real multi-touch | Yes — `Emulate Touch From Mouse` is editor-only |
| Frame rate | May vary in editor | Should be stable 60fps | Yes |
| Background colour | Matches project setting | Matches project setting | Same |
| Screen size | Fixed 360×780 preview | Scaled to device screen | Yes — `canvas_items` stretch handles this |

If the background colour or layout looks wrong on device but correct in the editor, check that `window/stretch/mode="canvas_items"` and `window/stretch/aspect="keep"` are set in `project.godot` (T002).
