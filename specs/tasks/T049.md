### Step 3 — Wire brick_hit through BrickGrid relay in Game.gd

> **Architecture amendment (BUG-3 / ADR phase6-system-map)**: Do NOT add `AudioManager.play("brick_hit")` directly in `Brick.gd`. `BrickGrid.gd` already emits `brick_hit(pos)` through its `_on_brick_hit()` relay. Putting the sound call in `Brick.gd` bypasses this pattern. Wire it through `Game.gd` instead, consistent with how `brick_destroyed` is handled.

Open `scenes/game/Game.gd`.

**In `_ready()`, after the existing `_grid.brick_destroyed.connect(...)` line, add**:
```gdscript
# Wire brick_hit through the BrickGrid relay (same pattern as brick_destroyed).
# [JS equiv]  this._grid.addEventListener('brickHit', this._onBrickHit.bind(this))
_grid.brick_hit.connect(_on_brick_hit)
```

**Add handler method** (near the other `_on_brick_*` methods):
```gdscript
## Called when a brick survives a hit (HP > 0 after decrement).
## Pos is the world position of the hit brick (unused here, available for particles).
func _on_brick_hit(_pos: Vector2) -> void:
	# [JS equiv]  audioManager.play('brickHit')
	AudioManager.play("brick_hit")
```

No changes to `Brick.gd` for the sound call — the signal relay already exists in `BrickGrid.gd`.

### Step 3b — AMEND: Replace anonymous lambda on _ball.lost in Game.gd

> **Architecture amendment (BUG-1 / ADR-006)**: `Game.gd._ready()` connects `_ball.lost` with an anonymous lambda: `_ball.lost.connect(func(): GameManager.lose_life())`. Anonymous lambdas CANNOT be disconnected. When T055 adds multi-ball and also connects `_on_ball_lost()`, every primary ball loss will decrement lives TWICE.
>
> This fix MUST be applied in T049 — before T055 is implemented.

Open `scenes/game/Game.gd`.

**In `_ready()`, replace**:
```gdscript
_ball.lost.connect(func(): GameManager.lose_life())
```

**With**:
```gdscript
# Named method — can be disconnected and does not double-fire with multi-ball (ADR-006).
# [JS equiv]  ball.addEventListener('lost', this._onPrimaryBallLost.bind(this))
_ball.lost.connect(_on_primary_ball_lost)
```

**Add the two handler methods** (place in the ball-events section of Game.gd):
```gdscript
## Primary ball lost handler. Delegates to shared counter logic.
## Separate from _on_ball_lost so extra-ball lambdas can call the same counter.
func _on_primary_ball_lost() -> void:
	_on_ball_lost()

## Shared ball-lost counter. Decrements _ball_count; only loses a life when all balls are gone.
## _ball_count starts at 1. Extra balls (T055) increment it before spawning.
func _on_ball_lost() -> void:
	_ball_count -= 1
	if _ball_count <= 0:
		# [JS equiv]  if (this._ballCount <= 0) { this._ballCount = 1; gameManager.loseLife() }
		_ball_count = 1
		GameManager.lose_life()
```

**Add the `_ball_count` variable** in the state section of Game.gd (near other `var _` declarations):
```gdscript
# Active ball counter for multi-ball (T055). Starts at 1 (the primary ball).
# [JS equiv]  #ballCount = 1
var _ball_count: int = 1
```
