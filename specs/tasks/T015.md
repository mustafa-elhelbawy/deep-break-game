### Step B1 — Install JDK 17

Godot's Android export pipeline requires JDK 17 exactly (not 11, not 21).

| OS | Command / Installer |
|----|---------------------|
| **Windows** | Download Adoptium Temurin 17 from **adoptium.net** → run `.msi` installer → check "Add to PATH" and "Set JAVA_HOME" |
| **Mac** | `brew install openjdk@17` → follow brew's post-install PATH instructions |
| **Ubuntu/Debian** | `sudo apt update && sudo apt install openjdk-17-jdk` |

**Verify**:
```bash
java -version
# Must print: openjdk version "17.x.x"

keytool -help
# Must not say "command not found" — keytool ships with JDK
```

---

### Step B2 — Install Android SDK (command-line tools only — no Android Studio)

1. Go to: developer.android.com/studio → scroll to "Command line tools only"
2. Download the zip for your OS
3. Unzip to:
   - Windows: `C:\Android\Sdk\cmdline-tools\latest\`
   - Mac/Linux: `~/Android/Sdk/cmdline-tools/latest/`
4. Add the `bin` subdirectory to your system PATH:
   - Windows: System Properties → Environment Variables → PATH → add `C:\Android\Sdk\cmdline-tools\latest\bin`
   - Mac/Linux: add to `~/.zshrc` or `~/.bashrc`:
     ```bash
     export ANDROID_HOME="$HOME/Android/Sdk"
     export PATH="$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"
     ```
     Then: `source ~/.zshrc`

5. Install required SDK components:
   ```bash
   # Accept all licences first — type 'y' at every prompt
   sdkmanager --licenses

   # Install the components Godot needs
   sdkmanager "platform-tools" "platforms;android-33" "build-tools;33.0.2"
   ```

**Verify**:
```bash
adb version
# Must print: Android Debug Bridge version X.X.X

sdkmanager --list_installed
# Must include: platforms;android-33, build-tools;33.0.2, platform-tools
```

### Step B3 — Install Godot 4.3 CLI on the Build Machine

Download the same Godot 4.3 stable binary used on the Mac (Standard, **not** .NET/C#).

| OS | Action |
|----|--------|
| **Windows** | Download `Godot_v4.3-stable_win64.exe` → rename to `godot.exe` → copy to `C:\tools\` → add `C:\tools\` to PATH |
| **Mac** | `brew install godot` or download `.dmg` → drag to `/Applications/` → `sudo ln -s "/Applications/Godot.app/Contents/MacOS/Godot" /usr/local/bin/godot` |
| **Linux** | Download `.zip` → extract → `sudo mv Godot_v4.3-stable_linux.x86_64 /usr/local/bin/godot && sudo chmod +x /usr/local/bin/godot` |

**Verify**:
```bash
godot --version
# Must print: 4.3.stable (or 4.3.stable.official)
```

### Step B4 — Configure Godot's Android SDK Path

This step requires opening the Godot editor once on the build machine.

1. Open Godot editor: `godot --editor` (or double-click the executable)
2. Open the project from the cloned repo folder
3. Go to **Editor → Editor Settings → Export → Android**
4. Set **Android SDK Path** to:
   - Windows: `C:\Android\Sdk`
   - Mac/Linux: `/home/<user>/Android/Sdk` (or `~/Android/Sdk`)
5. Close the editor

**Verify** (Godot will show errors in the export dialog if SDK is misconfigured — check in T016).

---

### Step B5 — Install Android Export Templates for Godot 4.3

Export templates are the pre-compiled Godot runtime for each platform. They are ~300 MB and specific to the Godot version.

**Option A — via editor (recommended)**:
1. Open Godot editor
2. Go to **Editor → Manage Export Templates**
3. Click **Download** next to Godot 4.3 stable
4. Wait for download to complete (~300 MB)

**Option B — manual install**:
1. Download `Godot_v4.3-stable_export_templates.tpz` from godotengine.org/download
2. In Godot editor: Editor → Manage Export Templates → Install from File → select the `.tpz`

**Verify**: Editor → Manage Export Templates should show Godot 4.3 with a green checkmark (not "Missing").

### Step B6 — Generate the Release Keystore (One-Time, Keep Forever)

The keystore signs the APK. Losing it means you can never update the app on Google Play under the same listing. Store it securely.

```bash
keytool -genkey -v \
  -keystore deep-break-release.keystore \
  -alias deep-break-key \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -storepass YOUR_STORE_PASSWORD \
  -keypass YOUR_KEY_PASSWORD \
  -dname "CN=Deep Break, OU=Game, O=YourName, L=City, S=State, C=US"
```

Replace `YOUR_STORE_PASSWORD` and `YOUR_KEY_PASSWORD` with real passwords (store in a password manager — do not use the same password for both).

**Store the keystore file** outside the repo — for example, `~/keystores/deep-break-release.keystore`.

**Share these three values** with the Mac developer (via password manager, not plain text):
```
DEEP_BREAK_KEYSTORE_PATH  = /path/to/deep-break-release.keystore
DEEP_BREAK_KEY_ALIAS      = deep-break-key
DEEP_BREAK_KEY_PASSWORD   = <the key password>
```

> **Why not commit the keystore?** A leaked keystore allows anyone to publish an update to your app on Google Play impersonating you. Never put it in version control, even in a private repo.

### Step B7 — Set Up Environment Variables

Set these in your shell profile (Mac/Linux) or System Environment Variables (Windows) so they are available every time you run the export command:

**Mac/Linux** (add to `~/.zshrc` or `~/.bashrc`):
```bash
export DEEP_BREAK_KEYSTORE_PATH="$HOME/keystores/deep-break-release.keystore"
export DEEP_BREAK_KEY_ALIAS="deep-break-key"
export DEEP_BREAK_KEY_PASSWORD="your-key-password"
```

**Windows PowerShell** (add to `$PROFILE`):
```powershell
$env:DEEP_BREAK_KEYSTORE_PATH = "C:\keystores\deep-break-release.keystore"
$env:DEEP_BREAK_KEY_ALIAS     = "deep-break-key"
$env:DEEP_BREAK_KEY_PASSWORD  = "your-key-password"
```
