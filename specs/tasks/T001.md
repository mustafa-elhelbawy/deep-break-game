### Manual Steps — complete these yourself after the agent finishes

**Step M1 — Install Godot 4.3 stable (if not already installed)**

1. Go to godotengine.org → Download → Godot 4.3 stable
2. Choose **"Standard" (not .NET/C#)**
3. Download `Godot_v4.3-stable_macos.universal.zip`, unzip it
4. Move `Godot_v4.3-stable_macos.universal` to `/Applications/` and rename it to `Godot.app`
5. First launch: right-click → Open (macOS Gatekeeper requires this on first run)
6. Confirm: in Terminal, run `ls /Applications/Godot.app` — should return the app bundle contents

**Step M2 — Install the godot-tools VS Code extension**

- Open VS Code → Extensions panel (⇧⌘X) → search `godot-tools` → install publisher `geequlim`
- OR in Terminal: `code --install-extension geequlim.godot-tools`

**Step M3 — Connect Godot editor to VS Code**

1. Open Godot editor (open the project at this repo's root — it will create `project.godot` in T002)
2. Go to **Editor → Editor Settings → Text Editor → External**
3. Check **Use External Editor**
4. Set Exec Path to: `/usr/local/bin/code` (run `which code` in Terminal if this path differs)
5. Set Exec Flags to: `{project} --goto {file}:{line}:{col}`

**Step M4 — Verify the Language Server connection**

1. With Godot editor open, open any `.gd` file in VS Code
2. Bottom status bar should show `GDScript` language mode (not Plain Text)
3. Hover over a built-in class like `Node` — a tooltip should appear
4. If no tooltip after 10 seconds: check Godot Editor Settings → Network → Language Server → Remote Port matches `6005` (the value in `.vscode/settings.json`)

**T001 is complete when** M4 shows a working tooltip. No Godot scenes or GDScript have been written yet — this task is environment only.

### Step B1 — Install JDK 17

| OS | Instructions |
|----|-------------|
| Windows | Download Adoptium Temurin 17 from adoptium.net → run installer → ensure "Add to PATH" is checked |
| Mac | `brew install openjdk@17` then follow brew's PATH instructions |
| Linux | `sudo apt install openjdk-17-jdk` |

Verify: `java -version` prints `17.x.x`

---

### Step B2 — Install Android command-line tools (no Android Studio needed)

1. Download "Command line tools only" from developer.android.com/studio#command-tools
2. Unzip to:
   - Windows: `C:\Android\Sdk\cmdline-tools\latest\`
   - Mac/Linux: `~/Android/Sdk/cmdline-tools/latest/`
3. Add the `bin/` subfolder to your system PATH (`sdkmanager` must be callable from terminal)
4. Run:
   ```bash
   sdkmanager --licenses        # accept all licences — type 'y' repeatedly
   sdkmanager "platform-tools" "platforms;android-33" "build-tools;33.0.2"
   ```

Verify: `adb version` prints a version string

---

### Step B3 — Install Godot 4.3 CLI on the build machine

Download the same Godot 4.3 stable binary as the Mac (Standard, not .NET). Add to PATH.

Verify:
- Mac/Linux: `godot --version` prints `4.3.stable`
- Windows: `godot.exe --version` prints `4.3.stable`

---

### Step B4 — Configure Godot's Android SDK path (one-time)

Open Godot editor once on the build machine with the project open:
- Editor → Editor Settings → Export → Android → Android SDK Path
- Set to the SDK root (e.g. `C:\Android\Sdk` or `~/Android/Sdk`)

### Step B5 — Install Android export templates for Godot 4.3

Inside Godot editor: Editor → Manage Export Templates → Download  
(requires internet, ~300 MB, one-time per Godot version)

### Step B6 — Generate the release keystore (one-time, keep the output safe)

```bash
keytool -genkey -v \
  -keystore deep-break.keystore \
  -alias deep-break-key \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000
```

Store `deep-break.keystore` in a secure location **outside the repo**. Record the alias and passwords in a password manager. Share the three values back to the Mac developer as environment variables:

```
DEEP_BREAK_KEYSTORE_PATH = /path/to/deep-break.keystore
DEEP_BREAK_KEY_ALIAS     = deep-break-key
DEEP_BREAK_KEY_PASSWORD  = <the password you chose>
```
