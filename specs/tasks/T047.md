## Part A — AI Agent Prompt

**Task**: Add ±5° random angle variation to wall and brick bounces in `Ball.gd`. This prevents the ball from repeating the same predictable path on every play. The existing `MIN_VERTICAL_SPEED` enforcement must re-run AFTER jitter is applied.

**Project context**:
- Working directory: `/Users/mustafa_elhelbawy/Documents/Work/deep-break-game`
- File to modify: `scenes/game/Ball.gd`
- Godot 4.3 GDScript. Tabs. `# [JS equiv]` on non-trivial lines.
- Jitter applies ONLY to wall and brick bounces — NOT to the paddle deflection (paddle already has full angle calculation).
- `MIN_VERTICAL_SPEED` clamp already exists at the bottom of `_move_and_reflect()`.

---

### Step 1 — Locate the bounce section in Ball.gd

In `_move_and_reflect()`, the relevant section is the `else` branch (non-paddle colliders):

```gdscript
else:
    _velocity = _velocity.bounce(collision.get_normal())
```

---

### Step 2 — Add the jitter constant

At the top of the file, in the `# ── Constants ──` section, add:

```gdscript
# Maximum random angle variation applied after each wall/brick bounce.
# ±5° in radians — small enough to not feel random, large enough to break repetition.
# [JS equiv]  const BOUNCE_JITTER_RAD = 0.0873  (5 * Math.PI / 180)
const BOUNCE_JITTER_RAD: float = 0.0873
```

---

### Step 3 — Apply jitter in the `else` branch

Replace:
```gdscript
	else:
		_velocity = _velocity.bounce(collision.get_normal())
```

With:
```gdscript
	else:
		_velocity = _velocity.bounce(collision.get_normal())
		# Apply a small random rotation to prevent perfectly predictable bounce patterns.
		# randf_range(-X, X) returns a float in [-X, X] — like Math.random()*2X - X in JS.
		# Vector2.rotated(angle) rotates the vector by 'angle' radians clockwise.
		# [JS equiv]  velocity.rotate(jitter)  (no built-in; use rotation matrix)
		var jitter: float = randf_range(-BOUNCE_JITTER_RAD, BOUNCE_JITTER_RAD)
		_velocity = _velocity.rotated(jitter)
```

---

### Step 4 — Verify MIN_VERTICAL_SPEED re-enforces AFTER jitter

The existing clamp block at the bottom of `_move_and_reflect()` already runs after all velocity modifications:

```gdscript
	# ── Enforce minimum vertical speed ────────────────────────────────────────
	if abs(_velocity.y) < MIN_VERTICAL_SPEED:
		_velocity.y = -MIN_VERTICAL_SPEED if _velocity.y <= 0.0 else MIN_VERTICAL_SPEED
		_velocity = _velocity.normalized() * _current_speed
```

This runs AFTER the jitter rotation — no changes needed here.

Then the final rescale:
```gdscript
	_velocity = _velocity.normalized() * _current_speed
```

Confirm this line is BELOW the jitter code and BELOW the MIN_VERTICAL_SPEED block. If not, move it there.

> **Why order matters**: jitter → enforce min vertical → rescale to exact speed. Running rescale before the MIN_VERTICAL_SPEED check would not break correctness (the check re-normalises if triggered), but the current order is cleaner.
