**Project context**:

- In normal mode: bricks start at y ≈ 60 (top margin) and grow downward.

- Brick grid is 7 columns × up to 12 rows; cell size is approx 48×22 px (based on 360-wide viewport).

### Step 1 — Understand current spawn layout

Read `BrickGrid.gd` to find:
- How `grid_pos: Vector2i` is converted to a world position.
- What the starting Y offset is.
- What `CELL_WIDTH`, `CELL_HEIGHT`, `MARGIN_TOP`, etc. constants are called.

The conversion is typically:
```gdscript
var world_x = MARGIN_LEFT + col * CELL_WIDTH + CELL_WIDTH / 2.0
var world_y = MARGIN_TOP  + row * CELL_HEIGHT + CELL_HEIGHT / 2.0
```

### Step 3 — Modify world position calculation

Inside the loop that converts `grid_pos` to world coordinates, wrap the Y calculation:

```gdscript
	var screen_h: float = get_viewport().get_visible_rect().size.y

	for descriptor in descriptors:
		var col: int = descriptor["grid_pos"].x
		var row: int = descriptor["grid_pos"].y

		var world_x: float = MARGIN_LEFT + col * CELL_WIDTH  + CELL_WIDTH  / 2.0

		var world_y: float
		if flipped:
			# Flipped: row 0 is near the bottom, rows grow upward.
			# MARGIN_BOTTOM mirrors MARGIN_TOP from the bottom edge.
			# [JS equiv]  const worldY = screenH - MARGIN_TOP - row * CELL_HEIGHT - CELL_HEIGHT / 2
			world_y = screen_h - MARGIN_TOP - row * CELL_HEIGHT - CELL_HEIGHT / 2.0
		else:
			# Normal: row 0 is near the top, rows grow downward.
			world_y = MARGIN_TOP + row * CELL_HEIGHT + CELL_HEIGHT / 2.0

		# ... rest of brick spawn logic (instantiate, position, add_child) ...
```
